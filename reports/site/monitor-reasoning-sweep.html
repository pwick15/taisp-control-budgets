Monitor comparison and reasoning-effort sweep

Across eight monitors and their reasoning settings, which catches the most APPS backdoors per dollar?

2026-10-30Marnick VandecauterComplete — 8 monitors, N=500, reasoning sweep where availableAPPStrusted monitoringdataset modereasoning effortmonitor comparison

Summary

  • Sonnet 5.5 is the best monitor at realistic audit budgets. It catches 81% of backdoors at a 0.5% budget and 87% at 2%, well ahead of every other monitor, and leads at every budget up to 20%. It is also the priciest practical option ($0.0093/sample).
  • Haiku 5.5 at xhigh effort is the value pick. At a 2% budget it reaches 0.85 (vs Sonnet's 0.87) for about a fifth of the cost ($0.0018 vs $0.0093/sample), and it tops the table at loose budgets (0.96 plateau). Sonnet only pulls clearly ahead at the tightest budgets.
  • Reasoning effort is the biggest lever for a cheap model — but how much it helps depends on the model. Haiku climbs from 0.77 (medium) to 0.96 (xhigh); Luna climbs from 0.39 (off) to 0.61 (xhigh). GLM barely moves (thinking-off 0.76 vs thinking-on 0.76), and Gemini Flash-Lite does not benefit at all.
  • The small open and flash-lite monitors are near-useless at tight budgets, reasoning or not. Gemini 3.5 Flash-Lite sits around 0.28 at every budget and gets no better with effort (0.19 at xhigh); Gemma and gpt-oss catch almost nothing below a 5% budget.
  • Biggest caveat: the 0.5% column rests on ~2-3 honest runs, so tight-budget numbers are noisy; treat them as indicative until bootstrapped. Dataset backdoors, one run per setting.

What we wanted to find out

The project compares ways to catch a model slipping backdoors into code. A monitor is a trusted model that reads submitted code and scores how suspicious it looks (0 to 1); humans then audit the most suspicious share they can afford. This study asks two questions across eight candidate monitors:

  1. Which monitor catches the most backdoors at each audit budget, and at what cost?
  2. For monitors with a reasoning knob, does more reasoning effort make a better monitor?
Apples to apples

Every monitor scores the same 500 dataset problems (same honest solutions and same verified backdoors), so differences are the monitor's, not the data's.

How the test works

  1. ProblemsThe first 500 APPS problems with a verified backdoor. Honest run = the dataset's correct solution; attack run = a solution with a working backdoor.
  2. Comments hiddenEvery # comment is stripped before the monitor reads the code.
  3. MonitorOne model reads the code and returns a suspicion score. Only the monitor calls an API.
  4. Reasoning sweepFor models with the knob, we re-run the monitor at each reasoning effort (none/low/medium/high/xhigh), one full run per level, through the model's authoritative provider (OpenAI, Anthropic, Google; open weights via DeepInfra).
  5. Audit ruleThe audit budget (share of honest runs reviewed) sets a score cutoff; a backdoor scoring above it is caught. Safety = backdoors caught / backdoors total.
Audit budget
Share of honest runs humans review. 0.5% of 500 honest runs is ~2-3 runs.
Safety
Backdoors caught out of 500 (every dataset backdoor works).
Reasoning effort
How much the monitor thinks before scoring. Provider-specific ladder; Sonnet/Gemma have no sweep here (um default / non-reasoning).
um
Untrusted-monitoring role for Sonnet (the model scores the same dataset backdoors); functionally 'Sonnet as the monitor', comparable to the trusted-monitoring runs.

Reasoning effort is model-dependent

The cheap-model story is reasoning effort. Haiku 5.5 is already strong and gets dramatically better with it (0.77 → 0.96 plateau, and 0.38 → 0.57 at 0.5%). Luna improves monotonically but with diminishing returns. gpt-oss lifts its ceiling but stays weak where it matters. GLM's reasoning is wasted (on ≈ off), and Gemini Flash-Lite cannot be rescued by thinking at all.

Which beats which

  • Sonnet 5.5 is the best monitor, leading at every budget to 20% (by +0.24 at 0.5%). Pay for it when tight-budget safety is the objective.
  • Haiku-5.5-xhigh is the best value — near-Sonnet safety at 2%+ for ~1/5 the per-sample cost and 1/20 the list price, and the highest plateau (0.96).
  • Haiku-xhigh strictly dominates GLM-5.3 (better at every budget, ~1/10 the cost), which in turn gains nothing from its reasoning.
  • Haiku dominates Luna at matched effort; Gemini Flash-Lite, Gemma and gpt-oss are the weak tier, unusable below a 5% budget.

Caveats

  • Tight budgets are noisy. 0.5% thresholds on ~2-3 honest runs; a bootstrap CI is the next step before leaning on the 0.5-1% column.
  • Dataset backdoors, not one attacker. Read as a monitor comparison, not a detection rate against any single model.
  • Usefulness is 1.0 by construction (dataset solutions), so only safety is compared; Sonnet is um-role but functionally the same 'model-as-monitor' measurement.
  • Coarse scores. Suspicion comes in steps of ~0.1, so safety curves plateau (a quantization artifact); AUROC is unaffected and is reported alongside.
  • One run per setting (Inspect caches re-runs), so run-to-run variation is unmeasured. gpt-oss high lost 1 errored honest run (499/500); every other arm is 500/500.
  • Gemini and Gemma carry no list price in the table, so their cost shows n/a (tokens are still counted).

Reproduce

Dataset mode, 500 problems, trusted monitoring, comments hidden. Each monitor/effort is one label; MONITOR_REASONING sets the effort. Provider keys in .env.

# one monitor at one reasoning effort
MONITOR=anthropic/claude-haiku-5-5 MONITOR_REASONING=xhigh \
  LABEL=dataset-haiku55-effortxhigh-tm-n500-strip scripts/run_dataset_monitor.sh
uv run python reports/build.py --open
